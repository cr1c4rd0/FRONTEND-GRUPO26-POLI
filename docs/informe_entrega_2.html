1. Introducción

El presente documento constituye el informe técnico de la Entrega 2 del módulo Front-End (Semana 5), correspondiente al Grupo 26 del Politécnico Grancolombiano. Durante la Entrega 1 (Semana 3), el equipo consolidó una propuesta integral de diseño y arquitectura de información para el portal periodístico digital SYNAPSE.TECH, plasmada en prototipos de alta fidelidad desarrollados en Penpot/Figma bajo un riguroso lenguaje visual contemporáneo enfocado en tecnología, inteligencia artificial y ciberseguridad.

En esta segunda fase, se procedió a la materialización completa de dichos mockups en código fuente estándar de la web utilizando HTML5 semántico, CSS3 moderno con variables CSS, Bootstrap 5.3 y JavaScript nativo (ES6+). Siguiendo las directrices académicas, la solución no requiere servidores backend propietarios ni bases de datos relacionales, garantizando su ejecución autónoma y fluida en cualquier navegador moderno mediante el consumo dinámico de datos estructurados en formato JSON y el almacenamiento local con Web Storage (localStorage).

2. Objetivos del Proyecto

2.1. Objetivo General

Construir la aplicación web interactiva correspondiente al portal tecnológico SYNAPSE.TECH a partir de los prototipos aprobados en la Entrega 1, garantizando una fidelidad visual milimétrica, una experiencia de usuario responsiva y accesible, y la integración de funcionalidades dinámicas en JavaScript para catálogo, favoritos, validaciones y administración básica de contenido.

2.2. Objetivos Específicos

  • Fidelidad Visual y Maquetación Semántica: Traducir fielmente la paleta cromática (#0A0D14, #12151F, #7C5CFF, #22D3EE), la tipografía (Space Grotesk e Inter) y los componentes visuales aprobados en la Semana 3.
  • Consumo Dinámico de Datos: Implementar una arquitectura modular en JavaScript para consumir, procesar y renderizar las noticias a partir de un archivo JSON estructurado (data/news.json).
  • Persistencia en el Cliente: Configurar el API de localStorage para almacenar y mantener el estado de las noticias agregadas a favoritos y las mutaciones realizadas por el usuario en tiempo real.
  • Validación Rigurosa de Formularios: Desarrollar lógica en JavaScript para la validación reactiva de campos obligatorios y verificación de patrones sintácticos de correo electrónico con expresiones regulares, proporcionando retroalimentación visual clara.
  • Mini CRUD Desacoplado: Diseñar un módulo administrativo que permita crear, previsualizar en vivo, editar y eliminar noticias del catálogo local sin requerir un motor de base de datos externo.
  • Autonomía y Portabilidad: Empaquetar la solución con rutas relativas estandarizadas para posibilitar su ejecución inmediata vía protocolo file:/// o mediante servidores locales estáticos.

Manejo de la Restricción CORS en Entornos Locales (file:///):
Los navegadores web imponen políticas de seguridad estrictas (CORS) que bloquean la función fetch('data/news.json') cuando una página se abre directamente con el protocolo file:///. Para satisfacer plenamente el requisito de renderizado dinámico desde JSON sin romper la autonomía local, js/storage.js implementa una estrategia híbrida: realiza la petición fetch a data/news.json cuando el sitio se sirve por HTTP/HTTPS; y si el navegador detecta una restricción de archivo local, carga de manera transparente el mismo dataset integrado como semilla en memoria. De este modo, la aplicación opera al 100% de sus capacidades tanto en servidores web como al hacer doble clic en el archivo HTML.

5. Arquitectura Técnica y Solución de Requisitos

5.1. Renderizado Dinámico desde JSON y Resiliencia CORS

Para satisfacer el requerimiento de que la información de las noticias no debe estar fija en el HTML, sino consumirse y renderizarse dinámicamente mediante JavaScript a partir de un archivo JSON local (ej. data/news.json), se diseñó el módulo js/storage.js con una función asíncrona de inicialización:

// js/storage.js — Inicialización asíncrona con consumo dinámico de JSON async function initStorage() { const isInitialized = localStorage.getItem(STORAGE_KEYS.INITIALIZED); if (!isInitialized || !localStorage.getItem(STORAGE_KEYS.NEWS)) { try { // Intento prioritario: Consumo del archivo local data/news.json const response = await fetch('data/news.json'); if (response.ok) { const data = await response.json(); localStorage.setItem(STORAGE_KEYS.NEWS, JSON.stringify(data)); } } catch (err) { // Fallback transparente si el navegador bloquea fetch por política file:/// console.info('Cargando catálogo local autónomo para SYNAPSE.TECH'); localStorage.setItem(STORAGE_KEYS.NEWS, JSON.stringify(DEFAULT_NEWS_SEED)); } if (!localStorage.getItem(STORAGE_KEYS.FAVORITES)) { localStorage.setItem(STORAGE_KEYS.FAVORITES, JSON.stringify(DEFAULT_FAVORITES_SEED)); } localStorage.setItem(STORAGE_KEYS.INITIALIZED, 'true'); } }

5.2. Persistencia en el Cliente mediante Web Storage (localStorage)

La persistencia en el cliente permite que el portal funcione como una Single-State Application sin requerir una base de datos externa. Toda la información mutada por el usuario (artículos creados en el Mini CRUD, noticias eliminadas, altas y bajas en la lista de favoritos) se serializa en cadenas JSON dentro del espacio de almacenamiento del navegador:

// js/storage.js — Abstracción del sistema de favoritos function toggleFavorite(newsId) { const favs = getFavorites(); const index = favs.indexOf(newsId); let isFav = false; if (index >= 0) { favs.splice(index, 1); // Quitar de favoritos } else { favs.push(newsId); // Agregar a favoritos isFav = true; } localStorage.setItem(STORAGE_KEYS.FAVORITES, JSON.stringify(favs)); updateGlobalFavCount(); // Sincronizar badges en tiempo real return isFav; }

5.3. Validaciones de Formulario en Tiempo Real con JavaScript

El formulario de contacto implementa dos niveles de control: verificación en tiempo real al escribir (evento input) para limpiar advertencias de inmediato, y validación estricta al someter (evento submit) para prevenir envíos incompletos o correos malformados:

// contacto.html — Validación reactiva en JavaScript y expresiones regulares const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/; form.addEventListener('submit', (e) => { e.preventDefault(); let isValid = true; if (!nombreInput.value.trim()) { nombreInput.classList.add('is-invalid'); errorNombre.classList.remove('d-none'); isValid = false; } if (!emailInput.value.trim() || !emailRegex.test(emailInput.value.trim())) { emailInput.classList.add('is-invalid'); errorEmail.classList.remove('d-none'); isValid = false; } if (isValid) { renderSuccessState(formContainer); // Transición visual sin recarga showToast('¡Tu mensaje ha sido enviado con éxito!', 'success'); } });

7. Conclusiones y Lecciones Aprendidas

  • Fidelidad y Rigor de Maquetación: La fase de prototipado en la Entrega 1 facilitó una implementación front-end ágil y coherente. El uso de tokens CSS permitió ajustar espaciados, tipografías y colores de manera centralizada.
  • Desacoplamiento Frontend/Datos: Separar la estructura visual en HTML del catálogo informativo en data/news.json demostró las ventajas de la arquitectura modular moderna, permitiendo que nuevas noticias se rendericen automáticamente sin modificar la maquetación.
  • Resiliencia en Ejecución Local: Diseñar la persistencia con un mecanismo de respaldo local resolvió el bloqueo de CORS al ejecutar la aplicación vía file:///, asegurando total portabilidad académica.
  • Usabilidad y Accesibilidad: La incorporación de validaciones en tiempo real, estados vacíos ilustrados y micro-animaciones contribuyó a una experiencia de usuario gratificante y accesible.
